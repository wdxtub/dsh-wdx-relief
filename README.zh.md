# WDX Relief

降低 DSH 日常使用心智负担的小功能集合。目前八个功能，**全部设置都在这个插件的配置里**。

> 侧边栏 **插件 → 已安装插件 → WDX Relief**，配置区在 bundle 页面下方。
> 不往 DSH 的 Settings 导航里插入页面；字段都是插件自己的 `Config`，写入后持久化到 profile 的 `cordis.patch.yml`。

## 功能

- **输入框下一句预测**：对话结束后用灰字猜你接下来要发的话，<kbd>Tab</kbd> 填入；打字隐藏，<kbd>Esc</kbd> 忽略。
- **输入框上的一行**（默认开启）：逐轮显示「这一轮到哪了」，固定放在输入框上方。**实时进度**：一轮运行超过设置的间隔（默认 10 分钟）还没给你回复时自动出现——即使工具一直在跑、一直在思考，只要没回你话就算——正文区的过程行已经在实时显示它现在在做什么（`正在分析请求` / `正在运行命令`）和思考内容，这行不再复述——运行中只剩一个脉冲点，也不再报正文区已经在算的耗时，而是直接显示「会话回顾」里这一轮最新一条**进度摘要**（前面带它被记下的时间点，如 `11:27`）——和面板里同一段文字，Host 按同一间隔用便宜模型写成「在解决什么、推进到哪」；只放一条、不带「1–20 分」这类时间标签，后台任务的进度留在任务组里不串进来，没有存下来的摘要时不硬凑一段；卡住时状态词才出现（「无新输出 12 分」、待批准带工具名、出错带原因）；结束态把「第 2 轮 · 用时 8 分 40 秒」压成 `#2 · ◷ 8:40`，正常完成只留一个绿点（蓝=运行中、绿=完成、红=出错、橙=等你反馈或卡住、灰=取消/中断）——省下的宽度让给摘要；单行只放状态、进度、摘要和后台任务；展开后给同一份回顾里的「回复」原文和摘要——这一轮的要求不再抄一遍，那是你刚发的话，没有新信息；之后按同一间隔往「会话回顾」记一条这个时间窗的**思路摘要**——用便宜模型写成「在解决什么、推进到哪」，动作清单不带命令参数、模型输出里的命令也会被过滤；模型失败时退回本地摘要。**没有模型活动的窗口不记**：等你回答、等审批、长命令半天没吐字都跳过，不再每 10 分钟写一条「没有新输出」；状态条会直接显示「等你回答 / 待批准」。**后台任务进度**：本轮结束（或停在等你回答）而任务还在跑时，读取它的实时输出，在本轮组下按同一间隔更新一条「它跑到哪了」——摘要结合这一轮你的要求、本轮最后回复和任务最近几行输出，用人话说明它在做什么、推进到哪、是否正常，而不只是「bash 还在跑」；同一个任务的进度单独归到「后台任务」组，不会因为跨了几轮就散到好几个轮次组；这一行还常驻「后台任务仍在运行 · 已运行 … · 最近输出 …」，只在有新输出时更新；不用再回会话问「跑完没」。编辑输入框时这一行照常显示，消息发出去（新一轮开始）才让位；行尾的「▾」展开完整内容——单行只留状态和进度，回复、摘要、后台任务和动作在下面的块里换行显示、超出可滚动（窄窗口也能从头读到尾），再点「▴」收起；「›」跳到「会话回顾」的这一轮：自动展开、滚动到它，并立刻重读一次历史，所以行上刚出现的摘要不会在面板里缺一条。语义摘要每轮用一次便宜模型，并在轮次结束时由 Host 兜底生成——切走会话、关掉面板、整页刷新都不会漏这一轮；活动流水本地生成、零模型调用。这一行永不进入模型上下文，生成过的摘要会留在右侧 WDX Relief 面板里。
- **WDX Relief 页面**（右侧栏，默认开启）：和 WDX Git 一样出现在右侧栏的工具列表里；顶栏也有一个并排的图标，点一下直接打开面板。页面用两个 Tab：默认「会话回顾」（可在设置里改成旁问）；「会话回顾」按轮次分组（按轮次排序，后台任务跑到很晚也不会让旧轮次浮上来）：同一轮的进度记录和摘要放在一组，组头显示轮次、条数、结束时间和这一轮时长，可折叠；最近 N 轮（默认 3，可在高级设置里改）里如果某轮停在助手提问、或在末尾留了「下一步 / 需要你」这类待办，会标「待跟进」；正在跑的那一轮要等结束才参与判断，已结束的轮次在运行中也保留标记；顶部可按「全部 / 摘要 / 进度 / 待跟进」筛选，支持「最新在前 / 最早在前」，每 30 秒自动刷新，清空前会再确认一次；「旁问」不进入主上下文。
- **旁问**：Tab 里的输入框和 composer 一样是圆角卡片，底部可以选旁问专用模型（窄的时候只显示模型图标）、右侧圆形按钮发送；问答只留在面板里，不写会话、不写命令日志，也不进入模型上下文，不改变主会话模型。
- **回复风格**：长度 **短 / 标准 / 详细**；风格 **默认 / 专业 / 亲和 / 直接 / 跟随我的风格**；可加最多 2000 字的自定义指令。
- **便于行动**（默认开启）：先给结果和下一步；能一句说清的不写一段；保留风险、失败条件和已授权该做的工作。
- **ELI5 模式**（默认开启）：注入一句「默认用 ELI5 的方式和我说话，如果我要求则深入讲解」；关掉后这句完全不出现。
- **工具调用泄漏守卫**（默认开启）：模型把工具调用直接写成正文（`<tool_call>` / `<invoke>` 信封）、这一步没有任何工具卡、turn 却正常结束时，当场检测并在同一轮内注入纠正让模型重发；损坏的那一步还会在模型可见面上被作废，fork 出去的会话首步会收到一份「历史里的坏样本不要模仿」简报。可在设置页「工具调用守卫」分组里开关、改提示语言和每轮上限。源自 `@irwdone/dsh-tool-call-leak-fix`（MIT）。

## 运行要求

- DSH Web profile；插件依赖 `connection`、`sessions` 与 `tools` 服务。
- 已配置默认模型。预测会把最近几轮对话作为 prompt 发给当前默认模型；旁问默认用当前会话模型，也可以在面板底部切到别的模型；三者都不写入会话日志、不触发 agent loop；「待跟进」标记只读当前会话的摘要记录。
- 语义摘要从第 1 轮用户消息后开始、每轮更新，先按你配置的便宜模型链尝试，再自动挑便宜模型，最后退回当前默认模型；模型失败时退回本地短拼接。活动流水不调用模型；进度摘要和语义摘要共用同一条模型链，模型失败时退回本地摘要。进度记录按设置的间隔（默认 10 分钟）一条、且只在有模型活动或后台任务新输出时写；后台任务进度读客户端 jobs 服务（`job.list` / `job.follow`，不消费模型那份输出），该服务缺失时自动关闭这一段。进度和摘要共用 `$DSH_HOME/wdx-relief/recaps.json`。

## 安装

在 DSH 侧边栏 **插件 → 添加插件** 输入：

```text
dsh-wdx-relief
```

或让 agent 调：

```text
plugin_manager install_bundle target = "dsh-wdx-relief"
```

或命令行：

```bash
dsh plugin --profile <profile> add dsh-wdx-relief
```

安装后启用；客户端模块会在下次页面加载时挂载。

本地开发时用 `link:` 安装当前目录的方式见 [docs/guide.md](docs/guide.md)。
