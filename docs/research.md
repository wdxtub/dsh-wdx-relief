## 1. 核心判据：每个功能 = 一次「注意力投递」

减负与否不由「聪不聪明」决定，由这次投递的六个参数决定：

| 参数 | 好的取值 | 坏的取值 |
|---|---|---|
| ① 触发 | 事件驱动 + 多重门控（离焦、最小轮次、冷却、内容相似度） | 定时器每轮都来、模型想说就说 |
| ② 密度 | 有硬上限，只显示**变化量** | 无上限报告、每次重述背景 |
| ③ 位置 | 纯 UI，**不进模型上下文**、不破坏 prompt cache | 作为会话内消息插入 |
| ④ 决策成本 | 纯读，看完无需回应 | 要接受 / 编辑 / 批准 / 回答 |
| ⑤ 生成成本 | 本地零成本，或便宜模型 + 预算 + 去重 | 主模型 + 全量 transcript + 高频轮询 |
| ⑥ 可退出 | 默认可关、有频率与成本上限、成本可归因 | 默认开且无开关、隐藏的模型调用 |

**①②③④ 决定省不省心智，⑤⑥ 决定会不会反过来加负**——翻车的功能多半死在 ⑤⑥，不是内容差。

反面教材：Claude Code 的 Agent Progress Summaries 用主模型每 30 秒扫一遍完整 transcript，只为生成 3–5 个词的状态行，实测占单人 8%–26% 花费，且没有官方开关。密度和位置都对，成本与可退出失控。

## 2. 几条影响设计的实证锚点（二手转述，正式引用需回溯原文）

- 外在认知负荷对绩效的负向关联约为内在负荷的 3 倍；**模型发起的任务切换是最强负向预测因子**。所以「更智能」≠「更主动」，静默优先 + 中断预算是必要设计。
- ProAgentBench：最好的模型判断「该不该主动打扰」只有 64.4%；precision 不够 → alert fatigue → 用户直接关掉功能。
- DORA 2025：90% 已在用 AI，吞吐升而稳定性降——验证、评审、可观测性比提示类更重要。
- context rot 经验阈值：有效上下文 <256k、利用率停在 ~75%、规则文件 <300 行。给人看的信息不该挤进这个预算。
- Agent 时代新增的负荷是**搬家不是删除**：语法记忆少了，验证税、上下文管理、监督控制、理解债多了。

## 3. 结论 → 本插件的开关

| 调研结论 | 本插件的落地 |
|---|---|
| 给人看的信息必须纯 UI、不进上下文（③） | 输入框上方那一行、右侧「会话回顾」全部不写会话、不写命令日志、不进下一次模型请求；摘要走 `ctx.llm.stream` |
| 零成本功能和烧钱功能必须分开开关（⑤⑥） | 四个独立开关：`recapActivity`（活动流水，本地零调用）、`recap`（逐轮语义摘要，每轮一次便宜模型）、`recapProgress`（久未回复时的进展）、`recapJobs`（后台任务进度） |
| 语义摘要必须便宜模型 + 预算 + 去重 + 兜底（⑤） | 便宜模型链（可配，留空自动挑 flash/mini/haiku）→ 默认模型 → 本地短拼接；按轮次内容缓存、inFlight 合并、相似度 ≥0.9 沿用上一句 |
| 折叠类必须配「一键展开回原文」 | 单行 ▸ / ▾ 原位展开，`›` 跳到「会话回顾」并展开滚到该轮 |
| ② 只显示变化量，别复述正文已有的东西 | 运行中只留脉冲点：DSH 过程行已经实时显示当前动作与思考，这行不再写「思考中 / 运行命令」；状态词只留给异常态和结束态 |
| 预测类的审批边界是核心分水岭 | 预测 **Tab 只填入、不自动发送**；打字即隐藏、Esc 丢弃。偏离目标时重写下一条比顺着建议改更清楚 |
| 侧问不该污染主上下文 | 旁问（对应 Claude Code `/btw`）：不写 transcript、不进 prompt、不改主会话模型，可换模型 |
| 回复风格 / 便于行动 / ELI5 | 直接削外在负荷里的「读长文」和「找下一步」；`actionable` 保留风险与失败条件，不因精简而丢信息 |
| 反模式：把 vigilance 变成系统默认值 | 工具调用泄漏守卫——模型把 tool call 写成正文时同轮检测并纠正重发，而不是等人去发现 turn 空转 |

## 4. 有意偏离调研的地方

1. **预测默认开**，调研把预测类排在 P2、建议默认关。这里的取舍是：它满足「纯起草 + 打字即隐藏 + Esc 退出」，④ 的决策链被压到一次 Tab；⑥ 有开关。真正的风险是锚定（建议里的动词把「看 diff」带向「提交/部署」），不做自动发送就挡住了最坏路径。
2. **recap 是逐轮级，不是会话级**。调研里 pi-recap / Claude Code Session Recap 的门控是「离开 3 分钟 + 失焦 + ≥3 轮」；DSH 的痛点在**长轮次**——一轮跑十几分钟、一直调工具，人回来要的是「这一轮到哪了」。所以换成每轮 `turn/end` 生成一次，离开门控让位给相似度去重 + 不进上下文 + 便宜模型三项兜底。
3. **`minTurns` 取 1**（第 1 轮就生成），比 pi-recap 的 3 更激进：DSH 会话首轮往往就是真任务，等到 3 轮才给定位等于没有。
4. **不暴露阈值**（间隔以外）：`minTurns`、相似度 0.9、词预算 40 都是实现常量。调研主张参数外露，但参数一多用户不会调，只会关掉；目前只把「多久没回复」`recapStallSeconds` 收进设置。
